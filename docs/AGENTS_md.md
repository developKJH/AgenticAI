AGENTS.md — 프로젝트 규칙 정의

Codex가 프로젝트 작업을 수행할 때 지속적으로 참고해야 하는 지침을 정의하는 파일입니다.

프로젝트의 목적, 기술적 맥락, 코딩 규칙, 테스트 방법 및 금지 사항 등을 작성해 두면 매번 동일한 내용을 프롬프트로 전달하지 않아도 일관된 작업을 수행할 수 있습니다.

AGENTS.md는 프로젝트의 Git 저장소에 포함하여 관리할 수 있으며, 팀원과 AI 에이전트가 동일한 프로젝트 규칙을 공유하는 데 활용할 수 있습니다.

1. AGENTS.md 작성 방법

1.1 자동으로 초안 생성하기

Codex CLI에서 다음 명령을 실행합니다.

/init

현재 프로젝트의 파일과 구조 등을 참고하여 AGENTS.md 초안을 생성합니다.

권장 작업 순서

초기 프롬프트를 통해 프로젝트의 목적, 요구사항 및 기술적 배경을 설명합니다.

프로젝트의 기본 구조와 주요 파일을 생성합니다.

/init을 실행하여 AGENTS.md 초안을 생성합니다.

생성된 내용을 검토하고 실제 프로젝트 규칙에 맞게 수정합니다.

이후 프로젝트 진행 과정에서 필요한 규칙을 추가하거나 갱신합니다.

빈 프로젝트에서 바로 /init을 실행하는 것보다 초기 프롬프트로 프로젝트의 목적과 방향을 먼저 설명한 후 실행하는 것이 좋습니다.

1.2 직접 작성하기

AGENTS.md는 Markdown 파일이므로 텍스트 편집기나 AI 프롬프트를 통해 직접 작성할 수도 있습니다.

자동 생성된 초안이 실제 프로젝트의 규칙과 다르거나 누락된 내용이 있다면 직접 수정합니다.

2. 작성할 내용

프로젝트의 특성에 따라 다음 항목을 포함할 수 있습니다.

구분

작성 내용

프로젝트 개요

프로젝트의 목적과 주요 기능

테스트

테스트 실행 방법 및 테스트 작성 규칙

빌드 및 린트

빌드, 정적 분석, 코드 검사 방법

코드 스타일

언어별 코딩 규칙 및 네이밍 규칙

아키텍처

폴더 구조 및 설계 원칙

의존성

패키지 매니저 및 외부 라이브러리 관리 방침

보안

민감정보 및 인증정보 취급 규칙

금지 사항

반드시 피해야 하는 작업 및 제한 사항

2.1 작성 예시

# 프로젝트 규칙

## 테스트
- 코드를 수정하면 항상 pytest를 실행해 통과를 확인합니다.
- 새 기능에는 반드시 테스트를 함께 작성합니다.

## 코드 스타일
- Python은 PEP8을 따릅니다.
- 코드 포매터는 black을 사용합니다.
- 함수와 변수명은 영어로 작성합니다.
- 주석은 한국어로 작성합니다.

## 의존성
- 새 패키지를 추가하기 전에 사용자에게 확인합니다.
- 패키지 매니저는 pip + requirements.txt를 사용합니다.

## 금지 사항
- main 브랜치에 직접 커밋하지 않습니다.
- 데이터베이스 마이그레이션은 사용자 확인 후 실행합니다.

3. 작성 원칙

실제 프로젝트에서 반드시 지켜야 하는 규칙을 중심으로 작성합니다.

모호한 표현보다 구체적이고 실행 가능한 지침을 작성합니다.

프로젝트의 폴더 구조와 주요 파일의 역할을 설명합니다.

테스트 및 빌드 방법은 실제 실행 가능한 명령어로 작성합니다.

불필요하게 긴 문서보다는 핵심 규칙을 간결하게 유지합니다.

프로젝트가 발전하면서 변경된 규칙은 AGENTS.md에도 반영합니다.

특정 디렉터리에만 적용되는 규칙은 해당 디렉터리에 별도의 AGENTS.md를 작성할 수 있습니다.

4. AGENTS.md와 Memories의 차이

프로젝트의 규칙을 관리할 때 AGENTS.md와 Memories의 역할을 구분해야 합니다.

구분

AGENTS.md

Memories (037번)

성격

정적이고 명시적인 프로젝트 규칙

동적으로 축적되는 작업 맥락과 참고 정보

목적

반드시 준수해야 하는 작업 기준 정의

이전 작업에서 얻은 유용한 정보의 회상

공유

Git에 커밋하여 팀원과 공유 가능

일반적으로 개인의 로컬 환경에서 관리

관리

사용자가 직접 작성하고 수정

AI가 작업 과정에서 관련 정보를 축적

활용

작업 수행 시 적용할 기준

작업 수행 시 참고할 보조 정보

핵심 원칙

프로젝트에서 반드시 지켜야 하는 규칙은 AGENTS.md에 작성합니다.

Memories는 반복 작업에서 유용한 맥락을 보조적으로 제공하는 역할로 활용합니다.

중요한 프로젝트 규칙을 Memories에만 의존해서 관리하지 않습니다.

5. AGENTS.md 검증 및 유지관리

작성한 AGENTS.md가 실제 작업에 적용되는지 확인합니다.

Codex를 프로젝트 루트에서 실행합니다.

프로젝트 규칙을 요약하도록 요청합니다.

Codex가 AGENTS.md의 주요 규칙을 인식하는지 확인합니다.

실제 작업을 수행하면서 규칙이 의도대로 적용되는지 확인합니다.

프로젝트 변경에 따라 규칙을 지속적으로 갱신합니다.

하위 디렉터리에 별도의 AGENTS.md를 작성했다면 해당 디렉터리에서 실행하여 추가 지침이 적용되는지도 확인합니다.

6. AGENTS.md 계층과 우선순위

AGENTS.md는 전역, 프로젝트, 하위 디렉터리의 세 가지 범위로 나누어 관리할 수 있습니다.

이를 통해 공통 규칙과 특정 영역에만 적용되는 규칙을 분리하고, 작업 위치에 따라 필요한 지침을 추가로 적용할 수 있습니다.

6.1 지침 파일 탐색 순서

① 전역 지침 (Global)

사용자의 Codex 홈 디렉터리에서 전역 지침을 탐색합니다.

기본 경로는 ~/.codex/이며, CODEX_HOME 환경 변수를 별도로 지정했다면 해당 경로를 사용합니다.

AGENTS.override.md가 존재하면 해당 파일을 사용합니다.

존재하지 않으면 AGENTS.md를 사용합니다.

두 파일이 모두 존재해도 하나만 선택합니다.

② 프로젝트 지침 (Project)

프로젝트 루트부터 현재 작업 디렉터리까지 하위 경로를 탐색합니다.

각 디렉터리에서 다음 순서로 파일을 확인합니다.

AGENTS.override.md

AGENTS.md

설정된 fallback 파일명

각 디렉터리에서는 위 후보 중 하나의 파일만 선택합니다.

일반적으로 프로젝트 루트는 Git 저장소의 루트 디렉터리를 기준으로 판단합니다. 프로젝트 루트를 찾지 못하면 현재 작업 디렉터리만 확인합니다.

③ 지침 병합 및 우선순위

발견된 지침 파일은 프로젝트 루트에서 현재 작업 디렉터리 방향으로 순서대로 병합(concatenate)됩니다.

상위 디렉터리의 지침이 먼저 적용됩니다.

하위 디렉터리의 지침이 나중에 추가됩니다.

동일한 규칙에 대한 충돌이 발생하면 더 구체적인 하위 지침을 우선하도록 작성합니다.

즉, 작업 위치에 가까운 지침일수록 해당 작업에 특화된 규칙을 정의합니다.

6.2 계층 구조 사용 예시

~/.codex/
└── AGENTS.md                         # 전역 기본 규칙

myproject/
├── AGENTS.md                         # 프로젝트 공통 규칙
│
├── services/
│   ├── payments/
│   │   └── AGENTS.override.md        # 결제 서비스 전용 규칙
│   │
│   └── users/
│       └── AGENTS.md                 # 사용자 서비스 전용 규칙
│
└── src/
    └── AGENTS.md                     # 소스 코드 관련 규칙

예를 들어 services/payments/에서 작업한다면 다음 지침이 적용됩니다.

~/.codex/AGENTS.md

myproject/AGENTS.md

myproject/services/payments/AGENTS.override.md

이때 services/payments/AGENTS.override.md는 같은 디렉터리에 있는 AGENTS.md를 대체하지만, 상위 디렉터리의 지침까지 제거하지는 않습니다.

6.3 AGENTS.override.md의 용도

AGENTS.override.md는 동일한 디렉터리에 있는 AGENTS.md보다 우선하여 선택되는 파일입니다.

특정 디렉터리에서 기존 지침을 대체하거나, 임시 또는 특수한 작업 규칙을 적용할 때 사용합니다.

사용 예시

services/payments/AGENTS.override.md

# 결제 서비스 전용 규칙

- 테스트는 npm test 대신 make test-payments를 사용합니다.
- API 키 회전 시 반드시 보안팀에 통보합니다.

일반적으로 다음과 같이 구분하여 사용합니다.

파일

용도

AGENTS.md

지속적으로 유지되는 기본 규칙

AGENTS.override.md

동일 디렉터리의 기본 규칙을 대체하는 특수 규칙

AGENTS.override.md는 반드시 필요한 경우에만 사용하는 것이 좋습니다. 불필요하게 사용하면 어떤 지침 파일이 실제로 적용되는지 파악하기 어려워질 수 있습니다.

7. 핵심 원칙

AGENTS.md는 AI에게 매번 프로젝트 규칙을 설명하지 않도록 만드는 지속적인 작업 지침입니다.

프로젝트의 핵심 규칙은 문서로 명시하고 Git으로 관리하여, 작업 환경이나 대화가 바뀌더라도 일관된 개발 원칙을 유지합니다.

참고 사항 (고급 설정)

다음 설정은 일반적인 프로젝트에서는 별도로 변경할 필요가 없지만, 지침 파일을 많이 사용하거나 기존 프로젝트의 문서 체계를 활용할 때 알아두면 유용합니다.

A. 지침 파일 크기 제한

Codex는 기본적으로 지침 파일을 불러올 때 project_doc_max_bytes 설정에 지정된 크기 제한을 적용합니다.

기본값은 32 KiB(32 × 1024 = 32,768바이트)입니다.

여러 디렉터리에 지침 파일을 분리하더라도 전체 지침의 크기 제한이 공유되므로, 파일을 무조건 분리하는 것만으로 크기 제한을 피할 수는 없습니다.

기본 설정

# ~/.codex/config.toml

# 기본값: 32 KiB

크기 제한을 늘리는 경우

# ~/.codex/config.toml

project_doc_max_bytes = 65536

위 설정은 제한을 64 KiB로 늘립니다.

일반적으로는 크기를 늘리기보다 불필요한 지침을 정리하거나 하위 디렉터리로 분리하여 필요한 작업 범위에서만 지침을 불러오도록 관리하는 것이 좋습니다.

B. Fallback 파일명 설정

기존 프로젝트에서 CLAUDE.md, CONVENTIONS.md 등 다른 이름의 규칙 파일을 사용하고 있다면 Codex 설정을 통해 해당 파일도 지침 파일로 인식하도록 할 수 있습니다.

설정 예시

# ~/.codex/config.toml

project_doc_fallback_filenames = [
    "CLAUDE.md",
    "CONVENTIONS.md"
]

위와 같이 설정하면 각 프로젝트 디렉터리에서 다음 순서로 파일을 탐색합니다.

AGENTS.override.md

AGENTS.md

CLAUDE.md

CONVENTIONS.md

기본 파일이 존재하면 fallback 파일은 추가로 읽지 않습니다. 따라서 같은 디렉터리에 여러 지침 파일을 무조건 병합하는 용도가 아니라, 기본 지침 파일이 없을 때 기존 문서를 대체 지침으로 활용하는 기능입니다.

활용 사례

기존 Claude Code 프로젝트의 CLAUDE.md 재사용

팀에서 사용하던 CONVENTIONS.md 활용

기존 문서 체계를 유지하면서 Codex 도입

두 설정 모두 ~/.codex/config.toml에서 관리하며, 설정 변경 후에는 새로운 Codex 실행 또는 세션을 시작하여 적용 여부를 확인합니다.
