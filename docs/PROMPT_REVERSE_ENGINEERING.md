## 1. 목적과 기본 원칙

AI와 대화하다 보면 처음에는 예상하지 못했던 좋은 결과물을 얻거나, 원하는 방향에 정확히 부합하는 답변을 얻는 경우가 있습니다.

이때 결과만 저장하는 데 그치지 않고, **어떤 요청과 맥락이 이러한 결과를 만들어냈는지 분석하여 재사용 가능한 프롬프트로 정리**할 수 있습니다.

이를 프롬프트 역설계라고 합니다.

다만 대화 기록만으로 실제 모델 내부에서 사용된 원래 프롬프트를 정확히 복원할 수 있는 것은 아닙니다. 목표는 원본 프롬프트의 완벽한 복제가 아니라, 결과를 재현할 가능성이 높은 실용적인 프롬프트를 만드는 것입니다.

역설계 시 다음 원칙을 따릅니다.

1. **결과 중심 분석**: 원하는 결과물의 특징과 품질 기준을 먼저 파악합니다.
2. **맥락 분리**: 특정 프로젝트에만 해당하는 정보와 다른 작업에도 재사용할 지침을 구분합니다.
3. **핵심 조건 추출**: 결과에 영향을 준 역할, 목표, 제약조건, 입력 자료, 출력 형식을 정리합니다.
4. **불확실성 표시**: 대화에 명시되지 않았지만 추정한 조건은 사실과 구분합니다.
5. **재사용성 확보**: 프로젝트명, 파일명, 데이터 등은 필요에 따라 교체할 수 있는 변수로 만듭니다.

## 2. 역설계 진행 절차

### 2.1 좋은 결과물 선정

먼저 역설계할 만한 대화를 선정합니다.

다음과 같은 경우에 활용할 수 있습니다.

- 원하는 형식과 수준으로 문서가 작성된 경우
- 복잡한 기술 문제의 원인과 해결 방법을 정확하게 도출한 경우
- 코드 구조나 설계 제안이 실제 프로젝트에 잘 맞았던 경우
- 반복적으로 사용할 수 있는 분석 또는 업무 절차를 얻은 경우

### 2.2 대화 맥락과 결과 분석

해당 대화에서 다음 요소를 추출합니다.

- 사용자가 처음 제공한 목표와 배경
- 작업에 필요한 기술적·업무적 맥락
- 사용자가 추가로 제공한 조건과 수정 요청
- AI가 수행한 분석 및 작업 단계
- 최종 결과물의 형식과 구체적인 특징
- 결과의 품질을 결정한 핵심 제약조건

특히 최초 요청만 분석하지 말고, 결과가 개선되는 과정에서 추가된 질문과 수정 지시도 함께 살펴봅니다.

### 2.3 재사용 가능한 프롬프트로 정리

분석한 내용을 다음과 같이 구분합니다.

| 구분 | 정리할 내용 |
|---|---|
| 역할 | AI가 어떤 관점과 전문성을 가져야 하는가 |
| 목표 | 최종적으로 어떤 결과를 만들어야 하는가 |
| 입력 맥락 | 작업에 필요한 배경과 자료는 무엇인가 |
| 작업 절차 | 어떤 순서와 방법으로 수행해야 하는가 |
| 제약조건 | 반드시 지키거나 피해야 할 사항은 무엇인가 |
| 출력 형식 | 결과물을 어떤 형식으로 제공해야 하는가 |
| 완료 기준 | 어떤 상태를 만족하면 완료인가 |

특정 대화에만 필요한 정보는 변수나 입력 항목으로 분리하여 다른 상황에서도 사용할 수 있도록 합니다.

## 3. 역설계 요청 프롬프트

아래 프롬프트를 좋은 결과를 얻은 대화에 적용합니다.

```text
현재 대화의 전체 내용과 최종 결과물을 분석하여,
이와 유사한 수준의 결과를 다시 도출할 수 있는
재사용 가능한 프롬프트를 역설계해줘.

단순히 대화 내용을 요약하거나 최종 답변을 다시 작성하지 말고,
어떤 요청과 조건이 해당 결과를 만들어내는 데 중요했는지 분석해줘.

다음 항목을 기준으로 정리해줘.

1. 최종 결과물의 특징
   - 사용자가 만족할 만한 핵심 결과는 무엇인가?
   - 결과물의 형식, 구조, 상세 수준은 어떠한가?

2. 핵심 입력 조건
   - 사용자가 제공한 배경과 맥락은 무엇인가?
   - 결과 도출에 중요했던 요구사항과 제약조건은 무엇인가?
   - 대화 중 추가된 수정 요청은 결과에 어떤 영향을 주었는가?

3. 작업 수행 방식
   - 어떤 순서로 분석하고 작업해야 하는가?
   - 어떤 판단 기준과 검증 방법이 필요했는가?

4. 재사용 가능한 프롬프트 작성
   - 특정 상황에 종속되는 정보는 [변수]로 분리한다.
   - 역할, 목표, 입력 맥락, 작업 절차, 제약조건,
     출력 형식, 완료 기준을 포함한다.
   - 불필요한 지시나 결과와 무관한 대화 내용은 제외한다.

5. 불확실한 부분 구분
   - 대화에서 명확히 확인되는 조건과 추정한 조건을 구분한다.
   - 실제 원본 프롬프트를 정확히 복원할 수 있다고 가정하지 않는다.

마지막에는 바로 복사하여 사용할 수 있는
완성된 프롬프트를 별도로 제공해줘.

가능하다면 해당 프롬프트를 다른 유사한 상황에 적용할 때
교체해야 하는 변수와 사용 방법도 설명해줘.
```

## 4. 도출한 프롬프트 검증

역설계한 프롬프트가 실제로 유용한지 확인하는 과정이 필요합니다.

### 4.1 원본 대화와 분리하여 테스트

가능하면 새로운 대화에서 역설계한 프롬프트를 사용합니다.

원래 대화의 세부 맥락을 그대로 이어받지 않아도 원하는 결과를 도출할 수 있는지 확인합니다.

### 4.2 결과 비교

다음 기준으로 원본 결과와 비교합니다.

- 핵심 요구사항이 반영되었는가?
- 결과물의 구조와 형식이 유사한가?
- 상세 수준과 품질이 기대에 부합하는가?
- 불필요한 내용이나 잘못된 가정이 추가되지 않았는가?
- 다른 유사한 상황에도 적용할 수 있는가?

### 4.3 프롬프트 개선

결과가 부족하다면 프롬프트를 수정합니다.

특히 누락된 맥락, 모호한 조건, 부족한 완료 기준을 보완합니다.

> 프롬프트 역설계는 한 번의 분석으로 끝나는 작업이 아닙니다. 실제로 다시 사용해 보고 결과를 비교하면서 프롬프트를 개선하는 과정까지 포함합니다.

## 핵심 원칙

**좋은 결과물을 얻었다면 그 결과를 재현할 수 있는 조건과 작업 방식을 추출하여 자산으로 축적합니다.**

이렇게 축적한 프롬프트는 반복 업무의 효율을 높이고, 향후 유사한 프로젝트에서 출발점으로 활용할 수 있습니다.
