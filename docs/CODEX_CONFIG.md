# Codex 실행 환경 설정 (`config.toml`)

Codex는 `config.toml` 파일을 통해 사용할 모델, 추론 강도, 실행 권한, 샌드박스 및 기타 기능을 설정할 수 있습니다.

초기 프롬프트가 AI에게 프로젝트의 목적과 작업 방식을 전달한다면, `config.toml`은 Codex가 어떤 실행 환경과 기본 조건에서 작업할지를 설정합니다.

> **참고:** Codex의 설정 항목과 지원 값은 버전에 따라 변경될 수 있습니다. 아래 예시는 설정의 개념을 익히기 위한 출발점이며, 실제 적용 전에는 [Codex 공식 Configuration Reference](https://developers.openai.com/codex/config-reference)에서 현재 지원 여부와 값을 확인합니다.

## 1. config.toml의 역할

`config.toml`은 Codex의 동작 환경과 기본값을 정의하는 TOML 형식의 구성 파일입니다.

기본 작성 방식은 `키 = 값`입니다.

- 문자열은 큰따옴표(`" "`)로 작성합니다.
- 주석은 `#`으로 작성합니다.
- 관련 설정을 그룹화할 때 `[섹션명]`을 사용합니다.

가장 간단한 예시는 다음과 같습니다.

```toml
# 사용할 모델
model = "사용 가능한 모델 ID"

# 추론 강도
model_reasoning_effort = "medium"
```

`model`에는 현재 로그인한 계정이나 작업 공간에서 사용할 수 있는 모델 ID를 지정해야 합니다. 특정 모델명을 무조건 복사하기보다 Codex에서 제공되는 모델 목록과 공식 문서를 확인합니다.

## 2. 설정 파일 위치와 적용 범위

Codex는 사용자 공통 설정과 프로젝트별 설정을 지원합니다.

| 구분 | 파일 위치 | 적용 범위 |
|---|---|---|
| 사용자 설정 | `~/.codex/config.toml` | 해당 사용자 환경의 Codex 작업 전반 |
| 프로젝트 설정 | `<프로젝트>/.codex/config.toml` | 해당 프로젝트에 한정된 설정 |

### 2.1 사용자 설정

개인적으로 선호하는 모델이나 기본 실행 환경을 지정할 때 사용합니다.

```text
~/.codex/config.toml
```

### 2.2 프로젝트 설정

특정 프로젝트에서만 필요한 설정을 지정할 때 사용합니다.

```text
프로젝트/
└── .codex/
    └── config.toml
```

프로젝트 설정은 해당 프로젝트를 신뢰한 경우에만 로드됩니다. 신뢰하지 않은 프로젝트에서는 프로젝트 범위의 설정이 적용되지 않을 수 있습니다.

프로젝트 설정 파일을 저장소에 공유할 때는 개인 경로, 인증 정보, 비밀 값 또는 특정 사용자 환경에 종속된 설정이 포함되지 않았는지 확인합니다. 모든 설정 키가 프로젝트 설정에서 허용되는 것은 아니므로 공식 레퍼런스의 제한도 확인합니다.

### 2.3 Windows와 WSL2 환경

Windows와 WSL2는 서로 다른 사용자 환경과 홈 디렉터리를 사용하므로 Codex를 각각 설치해 사용한다면 설정 파일도 별도로 관리해야 합니다.

예를 들어 WSL2 Ubuntu에서는 다음 경로를 사용합니다.

```text
~/.codex/config.toml
```

Windows에서는 Windows 사용자 프로필 아래의 `.codex/config.toml`을 사용합니다. 현재 Codex를 실행하는 환경에서 설정 파일을 확인해야 합니다.

## 3. config.toml 생성 및 편집

가장 간단한 방법은 Codex에게 현재 설정을 확인하도록 요청하는 것입니다.

```text
현재 사용 중인 ~/.codex/config.toml 파일을 확인해줘.

파일이 없다면 먼저 현재 Codex에서 사용할 수 있는 모델을 확인하고,
기본 모델과 추론 강도를 지정하는 최소 설정 파일을 만들어줘.

기존 설정이 있다면 임의로 덮어쓰지 말고 현재 내용을 먼저 보여줘.
```

직접 생성하거나 편집하려면 다음 명령을 사용할 수 있습니다.

```bash
# 설정 폴더 생성
mkdir -p ~/.codex

# 편집기로 설정 파일 열기
nano ~/.codex/config.toml
```

`nano` 대신 `vim` 등 원하는 편집기를 사용해도 됩니다.

## 4. 자주 사용하는 핵심 설정

### 4.1 모델 및 추론 강도

```toml
# 사용할 모델 ID
model = "사용 가능한 모델 ID"

# 추론 강도
model_reasoning_effort = "medium"
```

| 설정 | 설명 |
|---|---|
| `model` | Codex에서 사용할 모델을 지정합니다. |
| `model_reasoning_effort` | 모델의 추론 강도를 지정합니다. |

추론 강도는 모델에서 지원하는 범위 내에서 선택합니다. 일반적으로 `low`, `medium`, `high` 등의 값을 사용할 수 있으며, 지원 값은 모델과 Codex 버전에 따라 다를 수 있습니다.

- `low`: 비교적 간단하고 빠른 작업
- `medium`: 일반적인 개발 및 문제 해결
- `high`: 복잡한 설계, 분석 및 디버깅

### 4.2 샌드박스 모드

```toml
# 작업 공간 내부에서 파일 수정 허용
sandbox_mode = "workspace-write"
```

샌드박스는 Codex가 파일과 시스템에 접근할 수 있는 범위를 제한합니다.

| 설정 | 설명 |
|---|---|
| `read-only` | 읽기 중심으로 작업합니다. |
| `workspace-write` | 허용된 작업 공간 내부에서 파일 수정을 허용합니다. |
| `danger-full-access` | 샌드박스 제한 없이 광범위한 접근을 허용합니다. 보안상 주의가 필요합니다. |

처음 사용하거나 일반적인 개발 작업을 수행할 때는 필요한 범위만 허용하는 설정을 우선 고려합니다.

### 4.3 승인 정책

```toml
# 필요한 경우 사용자에게 승인 요청
approval_policy = "on-request"
```

승인 정책은 Codex가 명령 실행이나 추가 권한이 필요한 작업을 진행할 때 승인 절차를 어떻게 처리할지 지정합니다.

| 설정 | 설명 |
|---|---|
| `on-request` | 작업 상황에 따라 사용자 승인을 요청합니다. |
| `never` | 승인 요청을 하지 않습니다. 자동화 환경 등에서 사용할 수 있지만 실행 결과와 권한 범위를 신중하게 관리해야 합니다. |

지원되는 승인 정책은 버전에 따라 달라질 수 있습니다. 현재 공식 문서에서 지원하는 값을 확인합니다.

샌드박스와 승인 정책은 서로 다른 설정입니다. 샌드박스는 실행 가능한 작업의 범위를 제한하고, 승인 정책은 승인 요청을 처리하는 방식을 결정합니다.

### 4.4 기능 설정

Codex는 `[features]` 섹션을 통해 일부 기능 플래그를 설정할 수 있습니다. 기능 이름과 지원 여부는 버전에 따라 달라질 수 있으므로 아래 항목을 그대로 복사하기 전에 공식 설정 레퍼런스를 확인합니다.

```toml
[features]
# 예시: 현재 버전에서 지원되는 기능만 설정
# some_feature = true
```

기능 플래그를 활성화하는 것만으로 관련 스크립트, 규칙 또는 외부 도구의 설정까지 자동으로 완료되는 것은 아닙니다. 각 기능의 별도 구성 방법을 확인해야 합니다.

## 5. 기본 설정 예시

다음은 모델, 추론 강도, 샌드박스 및 승인 정책을 함께 지정하는 간단한 예시입니다.

```toml
# ==========================================
# Codex 기본 설정
# ==========================================

# 모델 및 추론 강도
model = "사용 가능한 모델 ID"
model_reasoning_effort = "medium"

# 샌드박스 및 승인 정책
sandbox_mode = "workspace-write"
approval_policy = "on-request"
```

이 설정은 학습을 위한 예시입니다. 실제 사용 환경에 맞게 모델 ID와 정책을 확인하고 조정합니다. `[features]` 항목은 필요한 기능과 현재 버전에서 지원되는 키를 확인한 뒤 별도로 추가합니다.

## 6. 현재 설정 확인

Codex CLI에서 다음 명령을 입력하면 현재 세션의 상태를 확인할 수 있습니다.

```text
/status
```

모델, 추론 강도, 실행 환경 및 권한 등 현재 세션과 관련된 정보를 확인할 수 있습니다. 표시 항목은 Codex 버전에 따라 달라질 수 있습니다.

설정 파일을 수정한 뒤에는 Codex를 다시 시작하거나 새 세션을 열어 변경 사항이 반영되었는지 확인합니다.

## 핵심 원칙

1. **초기 프롬프트와 설정 파일의 역할을 구분합니다.** 초기 프롬프트와 `AGENTS.md` 등은 프로젝트의 목적과 작업 지침을 전달하고, `config.toml`은 Codex의 실행 환경과 기본 동작을 설정합니다.
2. **필요한 설정만 지정합니다.** 모든 설정을 한 번에 추가하기보다 목적에 필요한 항목부터 적용합니다.
3. **권한은 최소한으로 부여합니다.** 샌드박스와 승인 정책을 함께 고려하고, 광범위한 접근 권한은 신중하게 사용합니다.
4. **공식 문서에서 지원 여부를 확인합니다.** 모델 ID, 설정 키 및 기능 플래그는 변경될 수 있습니다.
5. **환경별 설정을 구분합니다.** 사용자 설정과 프로젝트 설정을 구분하고, 프로젝트 설정에는 비밀 정보나 개인 환경 정보를 포함하지 않습니다.
